# AI 聊天功能改进建议

根据对当前代码库的分析，以下是针对 AI 聊天功能的三个核心改进建议，旨在提升系统的标准化、性能和用户体验。

## 1. 前端 Hook 标准化：迁移至 `useChat`
目前前端使用的是自定义的 `useChatStream.ts`，手动处理流协议解析（如 `0:`, `e:`, `d:`）。虽然这种方式提供了极大的控制权，但增加了维护成本。

### 建议操作
*   **迁移方案**：使用 Vercel AI SDK 提供的 `useChat` 钩子替换自定义实现。
*   **收益**：
    *   **代码精简**：减少约 40% 的手动状态管理代码（如 `isLoading`, `messages` 更新逻辑）。
    *   **鲁棒性**：自动处理流协议更新、重试机制和请求中止（AbortController）。
    *   **乐观更新**：内置支持消息发送后的即时 UI 反馈。

---

## 2. 流式协议优化：从 Text 到 Data Stream
当前的后端返回的是 `toTextStreamResponse`，主要通过文本流传输内容。

### 建议操作
*   **迁移方案**：将后端 `chat.ts` 中的响应改为使用 `createDataStreamResponse`。
*   **收益**：
    *   **多维数据传输**：允许在 AI 吐字的同时，通过同一个流异步发送非文本数据（如：检索到的知识卡片 ID、当前配额消耗、工具调用中间状态等）。
    *   **UI 联动**：前端可以根据流中的数据包，实时更新 UI（例如在消息下方动态显示“已找到 3 篇相关文档”）。

---

## 3. RAG 检索模型与链路优化
当前 RAG 检索（如 `knowledgeSearchTool`）是在 API 请求处理器中动态触发并等待的。

### 建议操作
*   **优化方案**：
    *   **异步预检**：利用推理模型（如 DeepSeek-R1 或 O1）的思考过程，在生成文本前并行触发检索。
    *   **流式状态反馈**：在执行检索时，通过 Data Stream 向前端发送“正在检索知识库...”的中间状态，消除用户的等待焦虑。
*   **收益**：
    *   **首字时间 (TTFT)**：通过更早的反馈减少感知延迟。
    *   **信息密度**：为 Socratic（苏格拉底）等复杂模式提供更丰富、更及时的上下文支持。

---

> [!NOTE]
> 当前系统的架构（尤其是 `client.ts` 中的多模型配置和健壮的 JSON 解析）已经非常优秀。上述改进建议属于从“产线级实现”向“行业顶尖标准”迈进的优化。
