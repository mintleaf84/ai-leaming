## 2026-11-20 · Web 覆盖率门禁 + 运维收口（W-COV / O1 / O3）

> 工单：Web 覆盖率门禁（W-COV1~3）+ 日志保留（O1）+ 告警通道（O2）+ zod 风险处置（O3）。

| 决策                | 选择                                                                                | 理由                                                                                                                                                                            | 备选/代价                                                                       |
| ------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 覆盖率门禁实现形态  | **`vitest` 原生 `coverage.thresholds`**（全局 + 6 条目录 glob），不照抄移动端的自定义 gate 脚本 | 移动端那套是为"分母由文件系统枚举"和棘轮基线文件写的，Web 侧 v8 已给出可信分母；原生阈值支持 glob，`npm run test:coverage` 一条命令就是门禁                            | 复用 `coverage_gate.dart` 思路：得再维护一份 baseline JSON 和 CLI，收益是 per-file 豁免 |
| 阈值口径            | **实测 −1pp 的 lines 棘轮**，按目录（services/api/auth/db/app/components）分档      | 只卡全局会被"服务层 84%"平掉"页面层 58%"；branches 受 mock 分支影响大，卡死会逼出无意义断言                                                                                     | 一次性设 80%：当前 app 层 58.87%，要么先补几千行测试，要么直接红                |
| 不做 `autoUpdate`   | **手动上调数字**                                                                     | 阈值自动跟随会让"本次降了但没降太多"静默通过，棘轮失效                                                                                                                          | autoUpdate：省一次改数字，代价是门禁慢慢变成橡皮筋                              |
| O1 清理哪些表       | **只清 `admin_logs` / `api_call_logs` / `api_audit_logs` / `web_vitals`**，`practice_logs` 永不清理 | 前四张是运维日志，`practice_logs` 是学习记录（归因、统计、SRS 的地基）；删错不可恢复                                                                                            | 按体积统一清理：多省几十 MB，风险是删掉用户作答历史                             |
| O1 失败语义         | **单表失败只记结构化日志、继续下一张表，等下一周期**                                | 日志清理是尽力而为的后台维护；一张表被锁不该让另外三张继续膨胀                                                                                                                  | 整批事务：一张失败全回滚，等于永远清不动                                       |
| O1 `web_vitals` 无索引 | **照旧 `DELETE ... WHERE created_at < ?`（全表扫）**，不做迁移加索引                | 该表只有 `(route, name, created_at)` / `(route, kind, created_at)` 复合索引，没有 created_at 前缀；日增百行、90 天窗口，扫描成本可忽略。要加索引得配一次迁移（本期不动 `_journal.json`） | 加 `idx_web_vitals_created`：更干净，但需要独立迁移 + 上线窗口，收益是微秒级     |
| O2 未配置 webhook   | **打印警告并 exit 0**，部署/回滚流程完全不变                                        | 告警是旁路。让"没配 webhook"卡住发布，等于用一个可选功能把可用性抵押出去                                                                                                       | 未配置即失败：安全，但会让首次部署无法进行                                     |
| O3 zod 高风险       | **不处理（不可达且已消除）**：zod 已是 `^4.6.6`（实装 4.6.7），`npm audit` 实测 0 high / 0 critical、advisory 里没有 zod 条目 | 「输入先经路由层校验」的前提成立（`validations/*` + `@hono/zod-openapi` 均在服务端），且降级到 3.x 会撞 `@hono/zod-openapi` 的 zod 4 peer 约束，纯亏 | 锁 3.x：需要同时回退 `@hono/zod-openapi` 与 `overrides`，破坏面远大于收益 |

### T-12 滚动模型归一（状态：**建议，待拍板**）

| 项   | 内容                                                                                                                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 现状 | `body{overflow:hidden;height:100%}` + `main{overflow-y:auto}` 全站内滚（`globals.css:419,425-429`、`layout.tsx:115`）；`overscroll-behavior-y:none` 写在 `html` 上其实是空操作（html 不滚） |
| 建议 | 改回 body 滚动 + 导航 `sticky top-0`；`main` 只保留 `min-h-0` 弹性链，去掉 `overflow-y-auto`；15 处 `100vh` 统一换 `100dvh`；`overscroll-behavior-y: contain` 挪到 body                     |

| 回滚 | 单 PR 可逆（只改 CSS + layout 结构），但必须与 T-14（长列表）分开做，否则排查"抖/卡"时无法归因                                                                                              |
