## 2026-11-13 · Agent API P1（鉴权地基）

| 决策              | 选择                                                                                                                                                      | 理由                                                                         | 备选/代价                                                       |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 全局 key 的身份   | `api_keys.user_id IS NULL` 视为**全局 key**，操作身份取 `API_GLOBAL_USER_ID`（缺省 `1`）                                                                  | 既有 key 全是"工具接入"性质，升级时不该强制绑用户；缺省 1 是种子里的站长账号 | 迁移时把 key 全部绑到 1：语义上把机器身份写成真人，后续无法区分 |
| 全局 key 的语义   | **只解决「是谁」，不解决「能做什么」**：它等价于站长身份，但**仍受 `scopes` 限制**（迁移后既有 key 默认 `read`，写接口会 403）。返回体带 `isGlobal: true` | 身份与权限分离，后面收紧只改 scope，不用再动身份模型                         | 让全局 key 绕过 scopes：一旦泄漏就是全站写权限，风险不可控      |
| 停用 key 的状态码 | 401（原实现是 403）                                                                                                                                       | 语义上"凭证不可用"就是未认证；403 留给"认证通过但作用域不足"，两个码不再混淆 | 保留 403：外部脚本已按 403 判停用会静默失效                     |
| 作用域模型        | `read` ⊂ `write` ⊂ `admin` 递进包含，存为单列文本                                                                                                         | 单列够用、SQL 可读；递进包含让"加权限"不必回填历史 key                       | 位掩码 / 关联表：为多角色组合预留，但本期无组合需求             |
| 审计范围          | 只记 `POST/PATCH/PUT/DELETE`，读请求不入库                                                                                                                | 读占绝大多数且无审计价值；审计表会被读流量淹没                               | 全量记录：写放大与清理成本都不可控                              |
| 审计失败          | 只 `logger.error`，不抛出、不阻断响应；写入放在 `after()` 里                                                                                              | 审计是旁路；写不进去不能把业务一起弄挂，也不能让 `busy_timeout` 拖慢响应     | 同步等待：写锁竞争时客户端要等审计落库                          |
| 审计挂载顺序      | 审计中间件在鉴权**之前**挂，但**只记能追溯到具体 key 的写请求**（403 记，401 匿名不记）                                                                   | 越权尝试要留痕；而完全匿名的 POST 不记，否则任何人刷请求就能把审计表灌满     | 401 也记：表无限增长且无法归因                                  |
| `last_used_at`    | `after()` 后台更新，非请求作用域退化为即时异步                                                                                                            | 不阻塞请求；单测直接调 `app.request` 时 `after()` 会抛，需该分支             | 直接 `await`：每请求多一次写                                    |
| 迁移写法          | 手写 `0011_*.sql`（`ADD COLUMN` / `CREATE TABLE IF NOT EXISTS`），不生成 drizzle snapshot                                                                 | 与 0009/0010 一致；快照缺失的既有状态不因本次改变                            | `drizzle-kit generate`：会从 0008 快照重新 diff，产出重复列     |

## 2026-11-13 · Agent API P2（只读接口）

| 决策            | 选择                                                                 | 理由                                                             | 放弃的方案                                                                     |
| --------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 路径前缀        | 沿用 `/api/external/*`（实际挂载是 `basePath("/api")` + `/external`） | 与 P1 和后台 curl 示例一致；同一份接口不应出现两个前缀             | `/api/v1/external`：无 rewrite，另起前缀会与 OpenAPI 里既有 path 重复            |
| 分页口径        | 统一 `limit`（默认 20、上限 100）+ `offset` + `meta{limit,offset,total?}` | agent 自生成调用代码时只需要一套分页约定                        | 每接口自定义参数：agent 每次都得读文档猜                                        |
| `/mastery` 形态 | 扁平条目（tag / 分数 / 正确数 / 总次数），不返回树                     | agent 做分析要的是可排序表格，不是 UI 的嵌套结构                  | 复用 `getMasteryTree`：嵌套且不含次数                                           |
| 错题统计口径    | 与错题列表一致：**排除已掌握**                                         | 两个接口数字对不上，agent 会得出矛盾结论                          | 统计含已掌握：更"全"但会自相矛盾                                                |
| 越权资源        | 一律 404，不回 403                                                    | 403 等于告诉对方"这个 id 存在"                                     | 403：泄露存在性                                                                |

| 误伤修正          | `welcome.ts` 里代码高亮示例字符串被替换，已还原 | 机械替换不区分字符串字面量；示例代码必须保持 `console.log`                       | 无                                                                        |

## 2026-11-11 · P0 四轮评审

| 决策                   | 选择                                                 | 理由                                                                                        | 备选/代价                                     |
| ---------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `.nvmrc` 的写法        | 写**最低版本** `20.19.0`，守卫脚本按 semver 比较     | 只写 `20` 时 nvm 可能选 20.18，而 `engines` 要求 `>=20.19.0`                                | 写死 20.20.2：CI/Docker 的 20.19 会被判不合格 |
| Playwright 复用 server | 回到 `reuseExistingServer: false`                    | 复用普通 dev server 时 `webServer.env`（`DB_FILENAME=test-e2e.db`）不生效，测试会打到真实库 | 复用：本地省事但可能污染数据                  |
| 棘轮 `--update` 语义   | 只允许持平或下降；放宽需 `--allow-increase "<理由>"` | 否则 `--update` 本身成为绕过闸门的后门                                                      | 自由更新：等于没有棘轮                        |
| eslint 异常退出        | status ∉ {0,1}、输出为空、非数组 → 一律失败          | 崩溃/被信号终止时 `status=null`，旧实现会把空报告当"0 条 warning"通过                       | 只判 total：会让崩溃伪装成通过                |
| Docker deps 阶段       | 额外 COPY `.nvmrc` 与 `check-node-version.cjs`       | `npm ci` 会执行 `preinstall`，缺文件会让镜像构建直接失败                                    | 去掉 preinstall：本机漂移不再拦               |
