# UI 审计（2026-11-20）

> 来源：一次基于代码证据的只读审计（web + 移动端），每条都有 `文件:行号`。
> 目标不是"更好看"，而是**把不一致收敛掉**、把缺失的状态补齐。
> 约束沿用既有决定：不引第三方 UI 组件库（`docs/mobile-ui-kit.md` §7）、Web 遵守 `docs/ui-system.md` 的硬约束。

## 现状一句话

移动端**缺一个颜色层**（20 屏里 16 屏把页面底/顶栏/正文色写死，切暗色只有 4 屏生效）；
Web **缺"请求失败"这一态**（6 处 `useQuery`，0 处解构 `isError`），接口挂了会显示成"没有数据"。

## 根因

1. **移动端没有颜色层**：`AppTheme` 的颜色是 `static const`，页面拿不到，于是各屏自己写 hex。
   → 新增 `AppColors extends ThemeExtension`（`mobile_app/lib/core/theme/app_colors.dart`），
   页面统一用 `context.colors.background/surface/border/text/textSecondary/success/error/warning`。
2. **Web 把"没数据"和"没请求到"当同一件事**：`useQuery` 不解构 `isError`，空态分支同时兜住两种情况。
   → 渲染顺序固定为 **loading → error → empty → 数据**；错误用既有的 `components/ui/error-state.tsx`（`onRetry` 必填）。

## 不做

1. **不引第三方 UI 组件库**（`getwidget`/`shadcn_ui`/`forui`）——病根是颜色没集中，不是组件不好。
2. **不单独发起"移除 screenutil"重构**：`.w/.h/.sp/.r` 共 1256 处，用户无感，只在本批收敛字号时顺带处理。
3. **不推翻刚合入的三批改造**（骨架 #230 / 过渡 #226 / 图标 #228）：只按例外清单补 2 个实心变体常量。
